title: "Install"
description: "Five steps you run yourself. One command each — or one command for all of them."
---

**One-time setup; after it the software stays current on its own.** By mail you get your pull-only **channel credential** (age-encrypted — see [the channel](channel)), the channel public key **`channel.pub`**, and your bootstrap parameters: registry path, channel name, pinned kit version.

## Step 1 — Bootstrap the kit

```bash
curl -fsSL <bootstrap-url> | bash -s -- \
  --registry channel.vexa.ai --channel <your-channel> --pubkey channel.pub
```

The tag resolves to a digest and the signature is checked against your key before anything unpacks; a bad signature writes nothing to disk. Also: `--version vX.Y.Z` (default `latest`), `--dest` (default `./vexa-kit`), `--keep-tarball`.

## Step 2 — Preflight

```bash
python3 kit/preflight/vexa_preflight.py --namespace vexa-staging
```

Nine checks, fails closed, every finding names its remedy. See [Preflight](preflight).

## Step 3 — Install

```bash
./kit/install.sh --provider <aws-eks|azure-aks|gcp-gke|generic|lke|openshift> \
  --registry channel.vexa.ai --channel <your-channel> \
  --channel-pubkey channel.pub --customer-values my-values.yaml
```

Idempotent. Installs pinned Argo CD, pinned Kyverno, your admission policy and the subscription. Production appears only with `--prod-pin <version>` — moving that pin is your gate. `my-values.yaml` is yours (start from `kit/profiles/vexa/customer-values.example.yaml`), applied over every release and never leaving your cluster. Also: `--registry-ca <pem>` for a private CA, `--registry-insecure` for a self-signed test registry, `--staging-ns`/`--prod-ns`, `--dry-run`. **No CLI access (OpenShift, shared clusters)?** Merge the signed station bundle chart into your config repo instead — see [OpenShift](environments/openshift).

## Step 4 — Smoke, with a human in a real meeting

```bash
python3 kit/smoke/vexa_smoke.py --namespace vexa-staging \
  --customer-values my-values.yaml --flows
```

Delivered set healthy → control plane answers → **you open a real meeting, admit the bot and speak while the CLI streams the transcript back** → flows tier answers. Output: a dated receipt naming chart revision, image digests, meeting id and segment count. Paste the **whole** meeting link:

| You paste | Dispatched as |
|---|---|
| `https://meet.google.com/abc-defg-hij` | `google_meet` |
| `https://teams.live.com/meet/<id>?p=<pass>` or `https://teams.microsoft.com/meet/<id>?p=<pass>` | `teams`, with passcode |
| `https://teams.microsoft.com/l/meetup-join/19%3ameeting_…` | `teams` |

An unrecognized link fails immediately. `--non-interactive` rehearses without the human phase and reports FAIL with no admitted bot.

## Step 5 — Send the station bundle back

```bash
python3 kit/validate/vexa_validate.py --namespace vexa-staging \
  --customer-values my-values.yaml --flows [--meeting-url URL | --non-interactive]
```

Runs steps 2–4 — add `--install` (with `--provider --registry --channel --channel-pubkey`) to run step 3 too. Exit codes: `0` pass · `1` phase failed · `2` usage · `3` redaction leak.

It writes **`station.tar.gz`**: your provider profile (`profile.env`), your values with every value under a key matching `password|token|secret|key|apikey` turned into `REDACTED`, the contract, the preflight and smoke receipts plus the raw smoke console, and `station.json`. `--verify-redaction` (on by default) re-extracts the finished archive and exits `3` if a removed value still appears, naming files, never values. Look at the file, then send it by hand — nothing transmits it.
